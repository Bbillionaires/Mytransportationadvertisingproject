# Risk Register

Severity: H/M/L. Owner: who must act. Items are marked **open** until the mitigation is verified.

| ID | Risk | Sev | Mitigation / status |
|---|---|---|---|
| R-001 | **Money transmission / marketplace licensing.** Collecting advertiser funds and paying creators and drivers may be regulated money transmission in some jurisdictions. | H | Use a licensed marketplace payout provider (D-026) so funds flow under their licenses; legal review before go-live. **Open.** |
| R-002 | **Database owner can bypass triggers.** Ledger immutability is trigger-based; the table owner or a superuser can disable triggers. | H | Mitigated (session 21): the API and jobs run every connection as `rmn_app` (SET ROLE), which owns no tables and is not a superuser: it cannot disable triggers or bypass RLS, and has no DELETE on journal or audit tables (`rls.test.ts`). Residual: whoever holds the owner/migration credentials; keep them in a release job only, with PITR backups and nightly hash-chain verification. **Partially mitigated.** |
| R-003 | **Tenant isolation was enforced only in application code.** | M | Mitigated (session 21): PostgreSQL row-level security on tenant tables (fleets, vehicles, devices and their codes/assignments/commands, drivers, invitations, memberships, integration keys, uploads, assets, creator channels, videos, geofences, reward programs, offers; owner-only writes on campaigns/creatives; billing rows), scoped per request to the signed-in user's organizations. A route that forgets its filter or permission check still cannot read or write another tenant's rows (`rls.test.ts`). Residual: system-scope paths (tablets, riders, keys, jobs) rely on their own authentication; campaigns are readable at the DB level for analytics joins (the API never returns other advertisers' campaigns). |
| R-004 | **Android tablet shell not verified on hardware.** Kiosk-mode behavior varies by OEM and EMM. | H | Session 14: shell built with Keystore key, origin-restricted bridge, lock task, boot start; builds, unit-tests and lints in CI; the web player runs end to end through a simulated bridge. Remaining: emulator instrumented test, one real tablet with the chosen EMM (D-017). **Open.** |
| R-005 | **Driver distraction / road safety.** Passenger screens or proximity alerts could distract drivers. | H | Rear-seat mounting only, no audio prompts by default, no driver-facing alerts, geofence alerts shown only on the passenger tablet. Safety review before pilot. **Open.** (Session 11: proximity alerts are silent, passenger-only, suppressed above 25 m/s, rate-limited.) |
| R-006 | **Children's privacy (COPPA and similar).** Passengers may be minors. | H | Guest mode collects no personal data; rider accounts restricted until counsel review (D-018). **Open.** (Session 11: rider accounts 18+ only; guests need no account.) |
| R-007 | **Gambling / sweepstakes law.** Jackpot-style games or random prizes. | H | Disabled (D-019). **Open.** |
| R-008 | **Content rights / DMCA.** Creator uploads may infringe; YouTube content must not be ingested without authorization. | H | Rights attestations (mandatory), takedown → immediate removal, counter-notice and restoration workflow, human review of every video (session 5). Remaining: DMCA agent registration, repeat-infringer policy, audio fingerprinting. **Partially mitigated.** |
| R-009 | **Invalid traffic / impression fraud** inflating payouts. | H | Phase 2: signed devices (done), nonce replay protection (done), validated vs. raw event separation, anti-idle heuristics, review holds. **Partially mitigated.** |
| R-010 | **Tax reporting** (1099-NEC/K, W-9/W-8 collection, sales tax). | M | Payout provider handling + tax advisor (D-016). **Open.** |
| R-011 | **Accounting treatment** (gross vs. net presentation, revenue recognition timing). | M | D-011; ledger keeps gross detail so reports can be restated. **Open.** |
| R-012 | **Audit log throughput.** The hash chain serializes inserts with an advisory lock. | L | Adequate for admin and financial actions. High-volume telemetry must go to a separate event store, not the audit log. Revisit (per-tenant chains or batch anchoring) at scale. |
| R-013 | **Allocation grain unresolved** (D-014), which changes creator/driver outcomes. | M | Per-batch default; must be fixed before live payouts. **Open.** |
| R-014 | **Seeded rule approvals are synthetic.** | M | Seed refuses to run when `NODE_ENV=production`; production rules must be drafted and approved by real, MFA-verified people. |
| R-015 | **No external penetration test yet; load characteristics were unknown.** | M | Load test built and run (session 21, `docs/LOAD_TEST.md`): 1,000 simulated tablets at about 155 req/s with no errors and p95 ≤ 50 ms after fixing the playlist bottleneck; CI runs a 300-tablet smoke test. **Open:** external penetration test before pilot. |
| R-016 | **Secrets management.** Keys live in Railway variables (sealed); some passed through chat during setup. | M | Session 27: key rotation built and tested (`docs/KEY_ROTATION.md`): versioned ciphertexts, `APP_ENCRYPTION_KEY_PREVIOUS` keyring, the worker re-encrypts on start and says when the old key can go; in-browser key generator for the owner; steps for AWS, bucket, database and metrics credentials. Remaining: actually rotate the keys that passed through chat (owner, a few minutes each); a managed KMS is optional later. **Mostly mitigated.** |
| R-017 | **Earnings expectations.** Drivers pay $30/month with no earnings guarantee; poor disclosure invites complaints and regulatory risk. | M | Transparent cancellation; estimate vs. approved earnings shown separately; no guarantee language anywhere (Phase 3–4 UI copy review). **Open.** |
| R-019 | **Advertiser/creator self-registration abuse.** | M | Mitigated (session 10): uniform 202 response (no enumeration), email verification required before paid or publishing features, rate limits, strong-password check. Residual: disposable email domains, bot sign-ups (add CAPTCHA if abused). |
| R-020 | **Overspend between allocations.** | M | Mitigated (session 6): delivery and billing both stop at total budget, daily budget and available advertiser funds; unbilled committed spend is reserved against the prepaid balance. Residual: refunds credited after delivery can still reduce funds below already-committed spend. |
| R-021 | **Media storage was local disk only.** | M | Built (session 23): S3-compatible object storage (Railway bucket as main store) with signed direct links; immutable originals; add-only backups to an AWS bucket with versioning + Object Lock (Governance) and optional second Railway bucket; nightly integrity audit with auto re-copy; restore with re-rendering; setup check that fails without a locked backup. Tested against a real S3 API (moto). **Open until** the buckets are created and `jobs:check-media-storage` passes in production (docs/MEDIA_STORAGE.md). |
| R-022 | **Abusive copyright notices** used to knock competitors' videos offline. | M | Notices require sworn statements; staff can see notice history; counter-notice restoration path. Add complainant verification and abuse tracking. **Open.** |
| R-023 | **ffmpeg parses untrusted files.** A malicious file could exploit a decoder bug. | M | Mitigated (session 21): ffmpeg/ffprobe may open local files only (no network fetches), run under prlimit (memory, CPU, file size, open files, no core dumps) with timeouts; the worker runs in a hardened container (internal network only, read-only FS, non-root, no capabilities, no-new-privileges, resource limits), verified end to end by `infra/media-worker/verify.sh` in CI. Residual: keep ffmpeg patched; consider gVisor or a separate VM at scale. **With Railway hosting** the worker must reach the bucket over the public network (Railway buckets have no private networking), so the no-internet network applies only to self-hosted/local storage; on Railway, ffmpeg's local-files-only input and prlimit remain, and an egress proxy allowing only the bucket host is the next step. |
| R-024 | **Budget checks scaled with event volume.** | M | Mitigated (sessions 21–22): playlist budget decisions cached 5 s per campaign (p95 490 → 50 ms at 1,000 tablets); trigger-maintained spend counters (migration 0017) replace per-play recounts, so validation stays at ~160 events/s regardless of history (was 117 → 75 and falling). Counters are verified equal to an exact recount in tests and nightly (`jobs:verify-spend-counters`, repairs and alerts). Residual: one validator process; shard by device if a single process is ever not enough. |
| R-025 | **Stripe integration not yet exercised against Stripe.** The REST client is unit-tested with a mocked transport and the flows run against an in-process simulator; no request has reached Stripe from this environment. | M | Execute the test-mode checklist in docs/PAYMENTS.md before any pilot. **Open.** |
| R-026 | **Under-reported or fabricated conversions.** Advertisers self-report orders; a dishonest advertiser could under-report, and a compromised key could inject orders. | M | Keys are scoped, hashed, revocable and audited; attribution requires platform touchpoints; single-use codes; contract audit rights (D-043); anomaly reports on redemption rates. **Open.** |
| R-027 | **One-time links sit in the email outbox until sent.** | L | Tokens are short-lived and single-use; bodies are purged after delivery; the outbox is readable only by the database runtime role. Keep the email job running every minute. |
| R-028 | **Browser-held tablet keys are weaker than hardware keys.** The web player's non-extractable WebCrypto key cannot be read by scripts, but a compromised OS/browser profile could still use it. | M | Production tablets use the Android shell (session 14: Keystore P-256 key, done). Session 25: hardware key attestation at enrollment, verified against Google's pinned roots and revocation list, shown in the fleet portal; `DEVICE_ATTESTATION=required` refuses unverified tablets (D-059). Remaining: confirm on a physical tablet; switch production to `required` once all tablets run the shell. **Mostly mitigated.** |
| R-029 | **Web player had no offline media cache.** | L | Mitigated (session 23): tablets cache playlist media (Cache Storage, 1.5 GB cap), play from the cache, and delete media the server stops listing; browser e2e plays with the network cut and checks an ended campaign's ad is removed. Residual: cached items still respect the playlist's short validity, so long outages stop playback by design (D-058). |
| R-030 | **Rider session token in phone `localStorage`.** Readable by any script on the origin if XSS existed. | L | Strict CSP (self scripts only), textContent-only rendering, 30-day expiry, revocation on sign-out/reset/deletion; rider tokens grant no access to staff or financial APIs. |
| R-018 | **Location privacy** for geofenced promotions. | M | Phase 5: on-device geofence evaluation where feasible, minimal retention, no trip history exposure. **Open.** (Session 11: coordinates never stored or logged; alerts keep only device/fence/time; no rider-location link.) |
| R-031 | **Tablets behind carrier NAT throttled by per-IP rate limits.** | M | Fixed (session 21): signed tablet requests are limited per device; other traffic per IP (`ratelimit.test.ts`). Residual: a forged device id only changes the bucket and still fails signature checks. |
